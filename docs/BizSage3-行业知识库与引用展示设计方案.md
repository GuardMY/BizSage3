# BizSage3 行业知识库与引用展示设计方案

**文档类型**：技术设计方案

**建设范围**：行业知识库、动态版本管理、证据引用与原始文档展示

**目标阶段**：P0 - 平台行业知识库

**状态**：建议评审

**日期**：2026-07-16

## 设计结论

将知识库建设为版本化、可审核、可追溯的证据系统，而不是将静态 Markdown 直接导入向量库。

- 检索只使用已发布且当前生效的资料版本。
- 每份报告固化当时使用的文档版本、原文片段与定位信息。
- 文档更新、替代或撤回不会改写既有报告的历史结论。
- 资料撤回后，历史报告保留正文与引用标记，但不再返回引用详情，也不提供原件预览或下载。
- 用户可从未撤回的报告引用打开经过授权的原始文档，并定位到支撑结论的原文。

## 目标与边界

### 建设目标

1. 让行业识别后的追问、归因和建议能够检索可信行业知识，而不是仅依赖模型通用知识。
2. 让报告中的关键事实、规则性判断和行业建议附带可读、可点击、可定位的来源。
3. 支持内部受控资料的上传、审核、发布、替代和撤回；不接入公开来源自动同步。
4. P0 仅建设平台公共知识库；客户私有资料、`owner_token_id` 隔离和组织模型均不进入 P0。

### 不应由 RAG 替代的能力

| 领域 | 正确实现方式 | 原因 |
| --- | --- | --- |
| 指标计算、环比同比、阈值判断 | 结构化指标、规则引擎、SQL/分析服务 | 结果必须可复算、可验证 |
| 会话关键上下文 | LangGraph 状态、结构化事实、会话摘要 | RAG 会遗漏关键轮次或引入过期信息 |
| 客户经营表格数据 | ETL、数据仓库或 SQL 聚合 | 表格数值不应只作为文本切片检索 |

RAG 主要服务于已完成内部审核的平台行业方法论、平台规则、指标定义、归因路径、脱敏案例与 SOP。公开来源资料不直接入库，也不自动同步。

## 与现有诊断流程的集成

保留现有 LangGraph 的场景识别、对话回合、等待输入和报告生成闭环。新增节点只提供证据上下文，不改变用户输入暂停与恢复机制。

```text
START
  -> scene_recognize
  -> retrieve_industry_knowledge
  -> conversation_turn
  -> await_input
  -> ...

生成报告：
  retrieve_report_evidence
  -> generate_report
  -> save_report_with_evidence
```

### 检索触发点

- **场景识别后**：根据行业、业务模式、经营阶段、诊断目标检索首轮指标口径、核心问题框架和提问策略。
- **对话回合中**：当用户出现新问题或关键异常时，按问题类型检索相关归因和追问依据。
- **报告生成前**：围绕已识别的问题、判断和建议重新检索，选取最终需要写入报告的证据。

### 模型接口变化

`conversation_turn` 和 `generate_report` 新增 `evidence` 参数。模型只接收服务端已授权、已过滤、已重排的精简证据集合。

```python
async def conversation_turn(
    messages: list[dict[str, str]],
    existing_facts: list[str],
    scene: dict[str, str],
    evidence: list[EvidenceContext],
) -> ConversationTurnOutput:
    ...
```

报告任务完成时，除保存 Markdown 和诊断结果外，还应保存 `report_evidences`，不能仅把引用混入 `Report.diagnosis` JSON。

## 知识库架构

```text
管理员上传内部受控资料
  -> 文档与版本元数据
  -> 原件存储
  -> 解析、OCR、切分、向量化、质检
  -> 审核并发布可检索版本
  -> 对话/报告检索并重排证据
  -> 报告固化证据快照
  -> 引用面板展示片段、定位和原始文档
```

| 层 | 职责 | 推荐实现 |
| --- | --- | --- |
| 原件存储 | 保存 PDF、DOCX、XLSX、HTML、Markdown、扫描件 | 开发环境使用受控 Docker volume；生产使用 S3 或 MinIO |
| 版本与权限元数据 | 管理状态、生效时间、归属、版本和哈希 | 现有 SQLAlchemy 数据库，作为唯一事实来源 |
| 解析与索引 | 抽取正文、页码、标题层级、OCR、切分与嵌入 | 异步 ingestion job，支持失败重试 |
| 检索服务 | 混合召回、元数据过滤、重排和证据组装 | 独立部署 Qdrant；关系数据库负责最终状态与授权校验 |
| 引用服务 | 生成稳定证据 ID、片段和定位 | `report_evidences` 快照表与受权预览 API |

向量索引不是权威数据源。Qdrant 作为独立的增量向量服务，仅保存可重建的向量与过滤 payload；文档发布、替代、撤回、版本和权限状态必须以关系型元数据为准。

## 内容范围

首批只纳入高可信、可维护且已完成内部审核的平台资料；不接入公开来源自动同步。

| 类型 | 典型内容 | 诊断用途 |
| --- | --- | --- |
| 行业方法论 | 指标口径、诊断框架、运营漏斗 | 决定问什么、如何解释指标 |
| 基准与规则 | 已审核的平台规则、内部行业报告、阈值说明 | 支撑对标、风险判断和合规提示 |
| 脱敏案例与 SOP | 异常排查路径、动作清单、复盘案例 | 生成可执行的优化方案 |

数值型行业基准应额外进入结构化 `benchmark_records`，带指标、口径、行业、时间范围、分位值和来源版本。RAG 负责解释和提供原文证据，计算和对比仍由确定性服务完成。

## 版本化数据模型

| 实体 | 关键字段 | 职责 |
| --- | --- | --- |
| `knowledge_documents` | `id`, `title`, `current_version_id`, `status` | P0 平台公共逻辑文档 |
| `knowledge_document_versions` | `document_id`, `version_no`, `sha256`, `storage_key`, `status`, `effective_from`, `effective_to` | 不可变版本、原件与生效区间 |
| `knowledge_chunks` | `version_id`, `chunk_no`, `content`, `locator`, `page_no`, `embedding_ref` | 可检索片段与原文定位 |
| `knowledge_ingestion_jobs` | `version_id`, `state`, `parser`, `error`, `indexed_at` | 解析、切分、嵌入和质检过程 |
| `report_evidences` | `report_id`, `version_id`, `chunk_id`, `quote`, `locator`, `query`, `rank`, `retrieved_at` | 报告证据快照与审计链路 |
| `benchmark_records` | `metric`, `segment`, `period`, `percentile`, `source_version_id` | 数值基准的可计算事实源 |

### 关键约束

- 更新资料时创建新版本，禁止覆盖旧版本。
- 每个 `report_evidences` 必须绑定精确的 `document_version` 与 `chunk`。
- 原件使用 `sha256` 保证可验证性。
- 文档版本状态与向量库 payload 中的状态保持同步，但线上最终权限检查必须回到数据库。
- P0 的 Qdrant payload 至少包含 `chunk_id`、`version_id`、行业元数据和版本状态；不包含 `owner_token_id` 或组织标识。

## 动态变更与发布生命周期

```text
草稿 -> 解析中 -> 待审核 -> 已发布 -> 已替代 / 已归档
                                  -> 已撤回
```

### 发布规则

1. 管理员上传已完成内部审核的资料后，创建独立版本并保存原件哈希。
2. 解析任务抽取正文、页码、章节、OCR 结果，生成切片和嵌入；完成前不参与检索。
3. 审核人检查来源、行业标签、切片质量和生效时间后执行发布。
4. 发布操作以原子方式切换当前版本，新会话只检索已发布且当前生效的版本。
5. 旧报告继续保留历史正文与引用标记；撤回后立即停止新检索，历史报告的证据详情接口不再返回该证据，原文预览和下载接口拒绝访问。

### 动态变更场景

| 场景 | 系统行为 | 用户可见结果 |
| --- | --- | --- |
| 行业口径更新 | 发布 `v3`，`v2` 标记为已替代 | 新报告引用 `v3`；旧报告继续显示 `v2` |
| 来源文件勘误 | 创建更正版本并设置生效时间 | 引用卡显示版本号与生效日期 |
| 资料撤回 | 立即从检索过滤中排除，并异步删除 Qdrant 对应向量 | 旧报告保留正文与不可点击的引用标记；不显示引用详情，也不提供原件 |

## 检索、重排与引用生成

### 过滤与召回

检索必须先执行硬过滤，再做混合检索和重排。

**硬过滤条件：**

- 文档版本状态为 `published`。
- 当前时间处于 `effective_from` 和 `effective_to` 生效区间。
- 行业、子行业、业务模式、经营阶段和资料类型匹配。
- 资料属于 P0 平台公共知识库范围。
- 当前用户对文档及原件具有访问权限。

**检索策略：**

1. 关键词检索与向量检索并行召回。
2. 按标题/章节命中、来源可信度、版本新鲜度、元数据匹配度和语义相关性重排。
3. 对话最多注入 3 至 5 个高置信片段；报告按结论选择必要证据，不拼接无关资料。

### 模型约束

模型输出必须区分：

- 用户明确提供的经营事实。
- 检索到的行业规则、基准或案例证据。
- 基于事实与证据形成的推断和建议。

模型不可自行编造文档标题、版本、页码或链接。服务端在保存报告前验证每个 `evidence_id`：该证据必须存在、已授权、处于本次检索候选集合，并且其版本与定位可追溯。

## 报告引用与原始文档展示

### 报告中的引用形式

关键结论后使用稳定引用标记：

```md
外卖转化下降更可能发生在菜单曝光至下单环节。[证据 1][证据 2]
```

引用标记只代表已保存的 `report_evidences`，不直接暴露对象存储链接。

### 引用来源面板

在现有报告页面增加“引用来源”侧栏或正文末尾区域。每条引用卡展示：

- 文档标题、来源类型、版本号和生效日期。
- 支撑结论的原文片段。
- 页码、章节路径或段落锚点。
- 当前状态：有效、已替代。
- “查看原文”和“下载原件”操作。

资料已撤回时，历史报告正文中的引用标记保持可见但不可点击；不渲染引用卡，也不返回文档标题、片段、定位、版本或状态等引用详情。

### 原文预览行为

| 文件类型 | 预览方式 | 定位方式 |
| --- | --- | --- |
| PDF | 浏览器 PDF 预览 | 页码与文本高亮 |
| Markdown / HTML | 清洗后的 HTML 预览 | 标题路径与段落锚点 |
| DOCX | 服务端转换的 HTML 或 PDF 预览 | 章节与转换页码；可下载原始 DOCX |
| 扫描件 | 页面图像与 OCR 文本并排展示 | OCR 坐标与页面位置 |

原始文件只能通过受权接口获得。后端完成鉴权后，返回短时签名 URL 或代理文件流；不得把公共存储 URL 写入报告或前端状态。

## 权限、隔离与审计

### 访问控制

- 平台行业资料可按全局范围发布。
- P0 只包含平台公共资料，不创建 `owner_token_id`、组织 ID 或租户范围字段。
- 向量查询必须携带权限过滤；检索候选返回后，服务端再次读取关系型元数据校验版本状态与访问权限。
- 原文预览和下载独立进行授权判断，且必须拒绝已撤回资料，不能只依赖前端隐藏按钮。

### 审计事件

至少记录以下事件：

- 上传人、审核人、版本创建、发布、替代、归档和撤回。
- 解析、OCR、索引和质检任务的结果与失败原因。
- 检索查询、命中文档版本、采用的报告证据。
- 原件预览与下载访问。

## 接口与模块边界

| 接口或模块 | 职责 | 访问角色 |
| --- | --- | --- |
| `POST /api/v1/admin/knowledge/documents` | 创建逻辑文档并上传原件 | 管理员 |
| `POST /api/v1/admin/knowledge/documents/{id}/versions` | 创建新版本并触发解析任务 | 管理员 |
| `POST /api/v1/admin/knowledge/versions/{id}/publish` | 审核并原子发布版本 | 管理员 |
| `POST /api/v1/admin/knowledge/versions/{id}/revoke` | 停止检索、删除 Qdrant 向量并隐藏历史报告引用详情与原件访问 | 管理员 |
| `KnowledgeRetrievalService` | 过滤、混合检索、重排和证据组装 | 服务端内部 |
| `GET /api/v1/reports/{report_id}/evidences` | 返回未撤回来源的报告证据摘要；撤回证据不返回详情 | 会话所有者或管理员 |
| `GET /api/v1/knowledge/documents/{id}/versions/{version}/preview` | 受权预览未撤回原文与定位 | 具备文档权限的用户 |
| `GET /api/v1/knowledge/documents/{id}/versions/{version}/original` | 下载未撤回原始文件 | 具备文档权限的用户 |

前端在 `ReportView` 增加 `EvidencePanel`；后端在报告生成任务结束时持久化 `report_evidences`。初期可在报告响应中返回引用摘要，稳定后采用独立证据查询接口。对于已撤回证据，前端只保留不可点击的引用标记，不能以缓存或降级逻辑展示引用详情。

## 实施阶段

| 阶段 | 交付内容 | 完成标准 | 优先级 |
| --- | --- | --- | --- |
| P0.1 | 内部审核资料的文档、版本、原件存储、解析任务、审核发布和撤回 | 可安全维护一批平台公共行业资料，草稿不会被检索 | 最高 |
| P0.2 | 独立 Qdrant、行业检索服务与工作流集成 | 对话和报告从独立向量服务获得经数据库状态校验的证据上下文 | 最高 |
| P0.3 | `report_evidences`、引用卡片、原文预览和下载 | 用户可从未撤回的报告引用定位并查看原始资料；撤回资料不泄露引用详情或原件 | 最高 |
| P1 | `benchmark_records`、监控和评测集 | 数值基准可计算，更新可回归验证 | 高 |
| P2 | 客户私有知识库、`owner_token_id` 最小隔离、多组织模型和细粒度审计 | 客户资料隔离、可检索、可追溯 | 中 |

## 验收标准

- 发布新版后，新生成报告不再引用已替代版本；关联资料未撤回时，已生成报告仍能查看生成当时的版本和片段。
- 资料撤回后，不会出现在任何新检索结果中；旧报告保留正文和不可点击引用标记，但不返回引用详情，也无法预览或下载原件。
- 每个未撤回报告引用都能验证到具体文档版本、切片、页码或段落定位、原件哈希和检索时间。
- P0 数据模型和 Qdrant payload 不包含 `owner_token_id`、组织 ID 或客户私有资料；所有可检索资料均为平台公共资料。
- 评测集覆盖行业匹配、版本新鲜度、撤回过滤、Qdrant 向量清理与关系型状态校验、引用真实性和原文定位成功率。

## 已确认决策

1. 权威资料范围：只收录内部审核资料；不接入公开来源自动同步。
2. 资料撤回后的历史证据策略：历史报告保留正文和引用标记，仅隐藏引用详情与原件访问。
3. P0 范围：只建设平台公共知识库；不预留 `owner_token_id`、组织模型或客户私有资料字段。私有资料能力延后至 P2。
4. 向量服务部署：使用独立 Qdrant 作为增量方案；关系数据库始终作为状态与授权的唯一事实来源。
