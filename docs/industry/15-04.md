# 交通运输 - 铁路运输行业知识库

## 1. 行业定义与边界

**交通运输**提供公路、水运、航空和铁路等人员或货物位移服务，资产利用率、时刻/运力、调度安全和服务可靠性是运营核心。本篇聚焦**铁路运输**：提供铁路客运、货运和站场服务，运力计划、列车兑现、装卸组织、线路安全和大宗客户合同是重点。其经营边界通常包括产品/服务设计、资源组织、交付和客户运营；若企业同时经营其他板块，应按业务单元拆分收入、成本、资产和客户数据。

## 2. 典型业务模式

- **价值交付**：以交通运输行业中的铁路运输产品或服务为核心，兼具标准化交付、定制项目、渠道交易或持续运营等形态。
- **收入来源**：主要来自产品销售、项目合同、服务费、佣金、订阅、租赁或增值服务，应区分折扣、返利、退款和代收款。
- **经营重点**：同时管理客户需求、资源投入、交付质量、价格毛利和回款，不能只用收入规模判断经营健康度。

## 3. 上游与采购管理

该行业主要上游包括：车辆、船舶、飞机、铁路设备、燃料、电力、场站、航线/路权、维修、保险和信息系统。供应与维修计划必须服从安全和运力可用性。针对铁路运输，采购应记录供应商资质、价格账期、交付承诺、验收结果、批次/序列号和替代方案，重点识别单一供应、长交期与质量认证约束。

## 4. 下游与客户运营

货主、旅客、货代、旅行服务商、制造商、贸易商和公共机构。时效、可达性、可靠性、价格和异常处置是客户价值。客户运营要串联线索/需求、报价、合同、订单、履约、验收、开票、回款和售后；应按客群、区域、渠道和业务单元分析转化、贡献毛利、服务成本与流失原因。

## 5. 核心运营流程

运力排班 -> 订单受理 -> 配载票务 -> 调度执行 -> 途中监控 -> 到达交付与结算。每个节点都应保留计划值、实际值、责任人、异常原因和改进结果；变更要同步影响的价格、成本、交期和风险。

## 6. 关键岗位与协作关系

典型岗位包括：运力计划、调度、驾驶/机组、站场、安全、维修、客服和结算人员。销售承诺、采购变更、交付验收、质量安全和财务结算应在同一业务对象下协同，关键审批和异常关闭需要留痕。

## 7. 运营指标与分析口径

首批建议指标如下，系统中应配置计算口径、时间范围、责任人和数据来源：

| 指标 | 建议口径 |
| --- | --- |
| 载运率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 班次兑现率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 准点率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 单位里程成本 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 事故事件率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |

## 8. 常见风险与控制

| 风险主题 | 控制建议 |
| --- | --- |
| 交通安全 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 天气事件 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 油价电价 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 设备故障 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 服务延误 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |

对铁路运输尤其需要关注其产品/服务特性、关键资源约束、客户集中度和现金流周期，不把通用行业做法直接当成企业事实。

## 9. 数字化与系统录入要点

- **组织与业务标签**：行业“交通运输”、子行业“铁路运输”、业务模式、客户类型、区域、经营阶段和责任组织。
- **经营对象**：按本行业实际选择产品/SKU、项目、合同、订单、批次、设备、资产、门店、站点或服务对象，并设置唯一编号。
- **过程事件**：需求、报价、采购、生产/交付、质检/验收、库存、物流、服务工单、变更、异常、开票和回款。
- **诊断字段**：计划值、实际值、差异值、差异原因、责任人、改进动作、截止日期、验证结果和关联凭证。
