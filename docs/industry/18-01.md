# 金融 - 银行行业知识库

## 1. 行业定义与边界

**金融**以资金配置、风险定价、支付结算和资产管理为核心，收入与风险高度绑定。审慎合规、客户适当性和资产负债管理优先于短期规模。本篇聚焦**银行**：经营存贷款、支付结算、财富管理和企业金融，资产负债匹配、信用风险、客户经营和合规运营相互制约。其经营边界通常包括产品/服务设计、资源组织、交付和客户运营；若企业同时经营其他板块，应按业务单元拆分收入、成本、资产和客户数据。

## 2. 典型业务模式

- **价值交付**：以金融行业中的银行产品或服务为核心，兼具标准化交付、定制项目、渠道交易或持续运营等形态。
- **收入来源**：主要来自产品销售、项目合同、服务费、佣金、订阅、租赁或增值服务，应区分折扣、返利、退款和代收款。
- **经营重点**：同时管理客户需求、资源投入、交付质量、价格毛利和回款，不能只用收入规模判断经营健康度。

## 3. 上游与采购管理

该行业主要上游包括：存款/资本、同业资金、金融基础设施、数据与征信、技术服务、渠道和专业人才。资金成本、数据质量和合规资质决定业务边界。针对银行，采购应记录供应商资质、价格账期、交付承诺、验收结果、批次/序列号和替代方案，重点识别单一供应、长交期与质量认证约束。

## 4. 下游与客户运营

个人、企业、机构投资者、政府平台和金融机构。客户关注资金可得性、价格、收益、流动性、速度和服务可信度。客户运营要串联线索/需求、报价、合同、订单、履约、验收、开票、回款和售后；应按客群、区域、渠道和业务单元分析转化、贡献毛利、服务成本与流失原因。

## 5. 核心运营流程

客户识别 -> 需求评估 -> 授信/承销/交易 -> 合同交收 -> 存续监控 -> 还款理赔清算。每个节点都应保留计划值、实际值、责任人、异常原因和改进结果；变更要同步影响的价格、成本、交期和风险。

## 6. 关键岗位与协作关系

典型岗位包括：客户、产品、风控、合规、运营、交易/承销、贷后保后、清算和数据人员。销售承诺、采购变更、交付验收、质量安全和财务结算应在同一业务对象下协同，关键审批和异常关闭需要留痕。

## 7. 运营指标与分析口径

首批建议指标如下，系统中应配置计算口径、时间范围、责任人和数据来源：

| 指标 | 建议口径 |
| --- | --- |
| 净息差/费率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 获客成本 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 逾期率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 损失率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 合规事件 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |

## 8. 常见风险与控制

| 风险主题 | 控制建议 |
| --- | --- |
| 信用风险 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 市场风险 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 流动性 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 欺诈洗钱 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 数据安全 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |

对银行尤其需要关注其产品/服务特性、关键资源约束、客户集中度和现金流周期，不把通用行业做法直接当成企业事实。

## 9. 数字化与系统录入要点

- **组织与业务标签**：行业“金融”、子行业“银行”、业务模式、客户类型、区域、经营阶段和责任组织。
- **经营对象**：按本行业实际选择产品/SKU、项目、合同、订单、批次、设备、资产、门店、站点或服务对象，并设置唯一编号。
- **过程事件**：需求、报价、采购、生产/交付、质检/验收、库存、物流、服务工单、变更、异常、开票和回款。
- **诊断字段**：计划值、实际值、差异值、差异原因、责任人、改进动作、截止日期、验证结果和关联凭证。
