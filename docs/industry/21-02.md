# 通信与数字基础设施 - 数据中心行业知识库

## 1. 行业定义与边界

**通信与数字基础设施**建设并运营连接、算力、存储和安全基础设施，为企业与个人提供稳定、可扩展和可计费的数字底座，资产利用率与服务等级是关键。本篇聚焦**数据中心**：建设和运营机房、机柜、服务器及托管服务，电力、制冷、上架率、可用性、安全与客户迁移决定收益。其经营边界通常包括产品/服务设计、资源组织、交付和客户运营；若企业同时经营其他板块，应按业务单元拆分收入、成本、资产和客户数据。

## 2. 典型业务模式

- **价值交付**：以通信与数字基础设施行业中的数据中心产品或服务为核心，兼具标准化交付、定制项目、渠道交易或持续运营等形态。
- **收入来源**：主要来自产品销售、项目合同、服务费、佣金、订阅、租赁或增值服务，应区分折扣、返利、退款和代收款。
- **经营重点**：同时管理客户需求、资源投入、交付质量、价格毛利和回款，不能只用收入规模判断经营健康度。

## 3. 上游与采购管理

该行业主要上游包括：机房、服务器、网络设备、光纤、电力、制冷、频谱/线路资源、软件许可、施工和安全服务。基础设施投资要与容量规划和能源成本联动。针对数据中心，采购应记录供应商资质、价格账期、交付承诺、验收结果、批次/序列号和替代方案，重点识别单一供应、长交期与质量认证约束。

## 4. 下游与客户运营

运营商、互联网、政府、金融、制造、园区、开发者和终端用户。客户关注覆盖、时延、可用性、弹性、合规和计费。客户运营要串联线索/需求、报价、合同、订单、履约、验收、开票、回款和售后；应按客群、区域、渠道和业务单元分析转化、贡献毛利、服务成本与流失原因。

## 5. 核心运营流程

容量规划 -> 站点/机房建设 -> 设备部署 -> 开通配置 -> 监控计费 -> 故障响应与扩容。每个节点都应保留计划值、实际值、责任人、异常原因和改进结果；变更要同步影响的价格、成本、交期和风险。

## 6. 关键岗位与协作关系

典型岗位包括：网络/云架构、基础设施、NOC/SRE、安全、容量、交付和资产人员。销售承诺、采购变更、交付验收、质量安全和财务结算应在同一业务对象下协同，关键审批和异常关闭需要留痕。

## 7. 运营指标与分析口径

首批建议指标如下，系统中应配置计算口径、时间范围、责任人和数据来源：

| 指标 | 建议口径 |
| --- | --- |
| 资源利用率 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 服务可用性 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 时延 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 单位资源成本 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |
| 故障恢复时长 | 按订单、项目、批次或资产分层统计，结合质量和现金结果解释 |

## 8. 常见风险与控制

| 风险主题 | 控制建议 |
| --- | --- |
| 大面积故障 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 网络攻击 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 数据泄露 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 容量不足 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |
| 供应商锁定 | 设置责任人、检查频率、触发阈值、处置动作和复盘证据 |

对数据中心尤其需要关注其产品/服务特性、关键资源约束、客户集中度和现金流周期，不把通用行业做法直接当成企业事实。

## 9. 数字化与系统录入要点

- **组织与业务标签**：行业“通信与数字基础设施”、子行业“数据中心”、业务模式、客户类型、区域、经营阶段和责任组织。
- **经营对象**：按本行业实际选择产品/SKU、项目、合同、订单、批次、设备、资产、门店、站点或服务对象，并设置唯一编号。
- **过程事件**：需求、报价、采购、生产/交付、质检/验收、库存、物流、服务工单、变更、异常、开票和回款。
- **诊断字段**：计划值、实际值、差异值、差异原因、责任人、改进动作、截止日期、验证结果和关联凭证。
