# BizSage3 数据源自扩展与可执行连接器设计方案

**文档类型**：技术与产品设计方案  
**目标阶段**：架构设计  
**日期**：2026-07-24  
**状态**：待确认、待实施

## 1. 背景与目标

BizSage3 需要接入店内 POS/ERP、CRM、财务、电商、外卖本地生活、广告平台，以及 Excel、截图、OCR 和人工补录等运营数据。标准平台可以预置连接器，但现实中会持续出现新的业务系统、私有 SaaS 和字段口径不同的数据源；逐个由研发团队手写接入，难以覆盖这一长尾需求。

本方案建设一种“数据源自扩展”能力：用户通过多轮对话描述或授权一个新数据源；子 Agent 在受控环境中完成发现、试采集和结构分析；平台据此生成真实存在、经过校验的连接器代码。代码作为该用户的数据源资源被平台托管、版本化、按需调用，并在用户批准后持续演化。

目标不是让 Agent 在生产环境自由执行或自由修改代码，而是建立一条可审计的软件资产生产链路：

```text
用户对话与授权
  -> 数据源发现与受控试采集
  -> 连接器规格与代码生成
  -> 安全、质量与契约校验
  -> 用户审批发布
  -> 云端隔离调度采集
  -> 运行证据与异常反馈
  -> Agent 提出新版本 -> 再次校验与审批
```

## 2. 已确认的产品边界

| 项目 | 结论 |
| --- | --- |
| 当前业务范围 | 先服务单店经营场景，数据模型和资源模型预留多店、多渠道及集团扩展能力。 |
| 数据接入形态 | 自动/定时同步优先；Excel、截图/OCR、人工补录同为核心入口。 |
| 新数据源接入 | 希望通过 AI 抽象通用接入方式，减少为每个来源新增业务代码的需要。 |
| 执行环境 | 云端，由平台进行租户隔离、调度和审计。 |
| 代码资产 | 连接器代码真实存在，经过安全校验后由平台按需调用。 |
| 用户维护方式 | 平台托管代码；用户通过对话、验证结果和版本审批维护，不查看或手动编辑代码。 |
| 本方案范围 | 聚焦数据源自扩展和可执行连接器，不包含“主 Agent 自主维护整个产品代码库”的能力。 |

## 3. 非目标

- 不让对话 Agent 直接持有永久凭据、直接访问生产数据库或绕过审批发布代码。
- 不把自然语言对话记录当作唯一的可执行采集逻辑。
- 不承诺无需新增平台能力即可支持所有私有协议、专有加密、图形验证或反自动化机制。
- 不把网页抓取、绕过访问控制或规避第三方反爬策略作为默认能力。
- 不在本阶段将连接器生成扩展为通用前端/后端功能自修改平台。

## 4. 核心概念

### 4.1 数据源资源

数据源资源（`DataSourceResource`）是归属于一个用户或未来租户的可调用能力，而不只是一次导入任务。它包含稳定资源标识、可调用操作、所有者、授权范围、当前发布版本、调度策略、运行状态和审计记录。

对业务层而言，它可提供如下能力：

- `test_connection`：在脱敏展示下测试授权与连通性。
- `discover_schema`：返回可采集对象和字段候选。
- `sync_full`：执行批准范围内的首次全量采集。
- `sync_incremental`：依据已保存的游标执行增量同步。
- `get_health`：查询最近成功时间、延迟、错误和数据质量状态。

### 4.2 连接器规格

连接器规格（`ConnectorSpec`）是 Agent 发现过程产生的结构化、可审计中间产物。它替代不可控的对话记忆，并作为代码生成、测试和版本比较的输入。

规格至少包含：

- 来源身份：名称、官网、接口文档、版本及支持对象。
- 授权方案：OAuth、API Key、服务账号、用户托管令牌或其他受支持方式。
- 采集流程：请求步骤、请求参数来源、分页、限流、超时、重试与幂等键。
- 数据契约：原始对象、字段路径、类型、时间语义、增量游标和删除/退款等变更语义。
- 标准映射：映射到 BizSage3 统一运营数据模型的规则、必填字段和口径说明。
- 运行权限：允许的目标域名、HTTP 方法、数据写入类型、最大同步频率和资源配额。
- 证据：文档引用、已脱敏的试采集样本、测试结果和已知限制。

### 4.3 连接器代码资产

连接器代码资产（`ConnectorArtifact`）是可执行的真实产物，而非提示词或脚本文本。一个已发布版本至少应具备：

- 经锁定的源代码、依赖清单和构建产物/镜像摘要。
- 由平台 SDK 提供的统一输入、输出、日志、密钥和网络能力。
- 可机器校验的数据输入输出契约和测试用例。
- 不可变版本号、构建签名、审批记录和可回滚的前一版本。

常规 REST/GraphQL 数据源优先生成到声明式运行时或标准 SDK 模板中；只有声明式能力无法覆盖的已授权流程，才生成受限的代码扩展。二者在业务层统一表现为数据源资源。

## 5. 总体架构

```text
                     ┌─────────────────────────┐
                     │ 用户对话与审批界面        │
                     └────────────┬────────────┘
                                  │
                     ┌────────────v────────────┐
                     │ 数据源编排 Agent          │
                     │ - 需求澄清                │
                     │ - 规格生成/修订           │
                     └───────┬─────────┬────────┘
                             │         │
              ┌──────────────v──┐  ┌───v────────────────┐
              │ 发现与试采集沙箱 │  │ 连接器生成器         │
              │ - 受限工具调用   │  │ - 配置/SDK 代码生成  │
              │ - 响应结构分析   │  │ - 测试样例生成       │
              └────────┬────────┘  └───┬────────────────┘
                       │               │
              ┌────────v───────────────v─────────┐
              │ 校验与发布流水线                   │
              │ 策略扫描 | 构建 | 测试 | 签名 | 审批 │
              └────────────────┬──────────────────┘
                               │
              ┌────────────────v──────────────────┐
              │ 用户数据源资源注册表                │
              │ 资源、版本、授权、调度、健康、审计  │
              └────────────────┬──────────────────┘
                               │
              ┌────────────────v──────────────────┐
              │ 云端 Connector Runtime             │
              │ 租户隔离 | 临时密钥 | 网络策略 | 队列 │
              └────────────────┬──────────────────┘
                               │
              ┌────────────────v──────────────────┐
              │ 标准化数据接入与质量层              │
              │ 口径映射 | 去重 | 游标 | 溯源 | 告警 │
              └───────────────────────────────────┘
```

MCP 可以作为连接器能力的标准工具调用边界，例如向平台暴露 `sync_incremental`。它不替代资源注册、密钥托管、调度、沙箱和数据写入控制；这些仍属于 BizSage3 的控制平面。

## 6. 生命周期与状态机

```text
草稿
  -> 发现中
  -> 待验证
  -> 待审批
  -> 已发布
  -> 运行中
  -> 异常待修复
  -> 已停用 / 已撤销

已发布或异常待修复
  -> Agent 生成候选版本
  -> 待验证
```

### 6.1 对话发现

Agent 一次只收集完成当前决策所必需的信息，例如数据源目标、可采集数据对象、授权方式、官方文档、样例文件/响应、刷新频率和业务口径。对话结束时必须形成结构化规格草稿，向用户清晰展示将访问什么、如何访问、将采集什么和已知限制。

### 6.2 受控试采集

试采集只能在隔离环境执行，使用短期或一次性授权；它允许读取已声明的低风险样本，不允许写入第三方业务系统。试采集输出应默认脱敏，并用于验证：

- 连通性和授权范围是否与声明一致。
- 对象、字段和分页是否符合规格。
- 时间字段、订单状态、退款/取消等语义能否正确映射。
- 增量游标是否可用，失败是否可恢复。

### 6.3 代码生成和校验

生成器基于经批准的模板和连接器 SDK 产生代码，禁止生成任意主机命令、任意网络目标或直接数据库访问。候选代码必须依次通过：

1. 语法、依赖许可和依赖漏洞扫描。
2. 静态策略检查：网络域名、HTTP 方法、文件访问、子进程、动态执行和密钥输出均受限。
3. 单元测试、契约测试和脱敏录制样本回放。
4. 沙箱集成测试，确认限流、重试、分页、游标和失败处理。
5. 数据质量检查，确认必填字段、类型、口径和来源元数据。
6. 构建、签名和生成用户可理解的变更摘要。

任一检查未通过时，产物不能进入审批和调度状态；Agent 只能提出修订方案或向用户补充询问。

### 6.4 审批发布与回滚

用户在界面中审批的是具体候选版本，而不是笼统同意“让 AI 修改连接器”。审批页面至少展示：访问域名、权限范围、采集对象、数据字段、刷新频率、试采集摘要、代码版本摘要和已知风险。

批准后，平台把不可变构建产物登记为发布版本，并可按授权调度。新版本必须先完成试运行或灰度任务；异常时自动停止该版本的后续任务，并可一键回滚到上一可用版本。撤销用户授权应立即停止新任务并使后续密钥租约失效。

## 7. 云端运行与安全边界

### 7.1 职责分离

| 组件 | 允许职责 | 禁止职责 |
| --- | --- | --- |
| 对话 Agent | 澄清需求、生成规格、解释结果、提出候选改动 | 直接执行生产同步、直接读取永久凭据、绕过审批发布 |
| 发现沙箱 | 在受限授权下试采集和分析结构 | 对外写入、访问未声明域名、访问生产数据存储 |
| 连接器生成器 | 从规格和模板生成候选资产 | 将未校验代码直接发布 |
| 发布流水线 | 扫描、测试、签名、登记版本 | 替代用户的审批决定 |
| Connector Runtime | 执行已发布版本并提交标准化数据 | 访问其他用户资源、无限制出网、直接拿到永久明文密钥 |
| 密钥服务 | 加密保存凭据、按短期租约注入 | 将凭据返回给模型、日志或前端 |

### 7.2 运行时控制

- 每次任务以用户/租户、数据源资源、版本和任务 ID 为隔离边界。
- 连接器仅可访问批准版本中的网络白名单，且受 DNS 重绑定、私网地址和重定向策略保护。
- 凭据由密钥服务按任务租约注入，日志、错误和 Agent 上下文必须进行脱敏。
- 连接器不得直连 BizSage3 业务数据库；只能使用带任务令牌的标准化写入 API。
- 任务受 CPU、内存、执行时长、并发、请求次数、响应体大小和同步频率限制。
- 每次调用记录资源版本、授权快照、请求摘要哈希、结果计数、游标变化、数据质量状态和错误分类。

### 7.3 数据与模型边界

若使用外部模型服务处理截图、单据、接口文档或样例响应，必须另行明确数据出境、脱敏、保留期限和供应商边界。在此决策完成前，平台应将敏感字段剔除或仅采用本地/自有模型能力；不得把完整凭据、原始订单明细或访问令牌放入模型上下文。

## 8. 数据契约与标准化

连接器运行结果不能直接作为模型上下文使用，必须进入统一的数据契约和质量层。每一条标准化记录至少携带：

```text
tenant_id / owner_id
source_resource_id / connector_version
source_object / source_record_id
observed_at / source_updated_at / ingested_at
mapping_version / data_quality_status
raw_reference / lineage_metadata
```

首期可围绕运营分析最常用的事实对象定义映射：订单/退款、商品与类目、库存流水、支付与费用、会员/客户、流量与广告、门店与渠道。对无法立即映射的字段，保留在受控原始载荷引用中，并标记为待确认口径，不能静默编造成标准指标。

## 9. 被动演化与主动诊断

本能力的“进化”是软件资产演化，不是模型参数在后台自行训练：

```text
用户新需求 / 同步异常 / 字段漂移
  -> 收集证据
  -> Agent 提出规格或代码候选版本
  -> 自动校验与试运行
  -> 用户审批
  -> 新版本发布或回滚
```

平台可沉淀不含用户凭据和私有业务数据的通用模板、SDK 组件和测试规则，以加速类似来源的创建。跨用户复用的只能是已经审查的通用能力；用户专属规格、连接器资产、运行日志和数据必须严格隔离。

接口授权失效、字段漂移或连续任务失败可以自动触发诊断和生成候选修复方案，但不得自动修改正在生产运行的版本。是否开启这类主动诊断、告警渠道和审批人策略，需要在实施前单独确认。

## 10. 分阶段实施建议

### P0：基础控制平面

- 建立数据源资源、版本、授权、审批、任务、审计和健康状态的领域模型。
- 建立密钥引用与短期租约机制，统一任务调度和标准化写入 API。
- 定义运营数据统一契约、来源溯源和基础质量校验。

### P1：模板化连接器

- 实现 REST/GraphQL、OAuth/API Key、常规分页、限流、重试和游标的声明式连接器运行时。
- 提供人工配置和 Excel/CSV 导入路径，验证数据契约和调度链路。
- 首先接入一个官方、只读、文档完整的代表性数据源，验证端到端流程。

### P2：Agent 辅助生成

- 实现对话澄清、规格草稿、样例响应分析和字段映射建议。
- 在沙箱中完成试采集、契约测试和用户审批展示。
- 让 Agent 生成声明式连接器配置，并建立版本、回滚和审计闭环。

### P3：真实代码资产与扩展 SDK

- 建立受限连接器 SDK、构建隔离、静态策略扫描、依赖锁定和制品签名。
- 对声明式能力不足但可合规授权的来源生成受限代码扩展。
- 将发布版本注册为可由平台调度或经 MCP 调用的用户数据源资源。

### P4：演化与运营化

- 增加字段漂移、授权失效、数据延迟和质量异常检测。
- 由 Agent 基于运行证据提出候选修复版本，支持试运行、灰度和回滚。
- 从已验证连接器提炼通用模板、测试夹具和映射规则。

## 11. 验收标准

1. 用户能通过对话创建一个新数据源的规格草稿，并看到访问范围、采集对象和字段映射。
2. 对支持范围内的来源，平台能在沙箱中完成授权测试和至少一次脱敏试采集。
3. 发布版本有真实、可追溯的代码或声明式构建产物，包含版本、依赖、测试和审批记录。
4. 未经审批的候选版本无法进入生产调度；运行中的版本无法被 Agent 静默改写。
5. 平台可按需或定时调用指定用户、指定资源、指定版本的连接器，并完成全量或增量数据写入。
6. 凭据不出现在代码、前端、普通日志、模型上下文或其他用户的运行环境中。
7. 同步数据可追溯至数据源资源、连接器版本、采集时间、源记录和映射版本。
8. 授权撤销、任务异常和版本回滚能够阻止后续不受控采集，并保留完整审计记录。
9. Excel/CSV、截图/OCR、人工补录仍可通过统一数据契约进入系统，不因自动连接器能力而被排除。

## 12. 实施前待确认事项

以下事项会影响具体实现和上线范围，需在进入开发计划前逐项确认：

1. 第一批允许接入的数据源类型、供应商和仅只读的授权范围。
2. 用户提供凭据的方式、密钥托管策略、撤销方式和合规责任边界。
3. 是否允许外部模型服务处理接口文档、截图/OCR 和脱敏样例数据。
4. 是否只允许官方 API 或明确授权接口；非标准来源的支持与合规边界。
5. 连接器发布审批人、试运行频率、灰度规则和紧急停用权限。
6. 是否启用基于异常的自动诊断，以及诊断结果的通知与修复审批流程。
7. 数据保留、原始载荷存储、脱敏、审计留存和删除策略。
